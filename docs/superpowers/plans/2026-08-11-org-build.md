# Org Build Adaptation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the provider image buildable with a single `docker buildx build` that compiles the Go binary inside a multi-stage Dockerfile, parameterized for a restricted-network org (private registry + private Go module proxy), with no GitHub Actions or `build/` submodule required.

**Architecture:** A self-contained multi-stage `Dockerfile` at the repo root builds the binary in a `golang:1.25.11` stage and copies it into a `distroless/static` runtime stage. A thin `hack/build-image.sh` wrapper (invoked by the org CI pipeline, or by a new `make build-image` target) passes private-registry settings via env vars → build args. GitHub Actions workflows are deleted.

**Tech Stack:** Docker BuildKit (multi-stage build, cache mount), Go 1.25.11, bash, GNU Make.

## Global Constraints

- Go version must be `1.25.11` (matches `go.mod` and existing CI).
- Module path default `github.com/jeremywyx/provider-harness`; must be overridable via build arg (org path may differ).
- Runtime base image MUST stay `distroless/static` pinned to `sha256:d9f9472a8f4541368192d714a995eb1a99bab1f7071fc8bde261d7eda3b667d8` (may be prefixed with `BASE_REGISTRY`).
- Binary path in runtime image: `/usr/local/bin/harness-provider`; `ENTRYPOINT ["harness-provider"]`; `USER 65532`.
- Image build must NOT require the `build/` git submodule to be initialized.
- No GitHub Actions workflows may remain in `.github/workflows/`.
- Version baked in with ldflag `-X ${MODULE_PATH}/internal/version.Version=${VERSION}`.
- Script must be strict (`set -euo pipefail`) and pass `shellcheck` if available.

### Task 1: Multi-stage root Dockerfile

**Files:**
- Create: `Dockerfile` (repo root)
- Verify against existing: `cluster/images/provider-harness/Dockerfile` (old single-stage image — keep it, out of scope to delete)

**Interfaces:**
- Consumes: nothing (first task)
- Produces: `Dockerfile` with build args `BASE_REGISTRY`, `GOPROXY`, `GOSUMDB`, `GONOSUMDB`, `MODULE_PATH`, `VERSION`; builder output `/out/harness-provider`; runtime binary `/usr/local/bin/harness-provider`; entrypoint `harness-provider`

- [ ] **Step 1: Create the Dockerfile**

Write exactly this to `Dockerfile`:

```dockerfile
# Build stage: compiles the provider binary inside the image.
# All network access flows through the Go module proxy (GOPROXY/GOSUMDB).
ARG BASE_REGISTRY=gcr.io
FROM ${BASE_REGISTRY}/golang:1.25.11 AS builder

ARG GOPROXY=https://proxy.golang.org,direct
ARG GOSUMDB=sum.golang.org
ARG GONOSUMDB=""
ARG MODULE_PATH=github.com/jeremywyx/provider-harness
ARG VERSION=0.0.0

WORKDIR /src
COPY go.mod go.sum ./
RUN --mount=type=cache,target=/go/pkg/mod \
    go mod download

COPY . .
RUN CGO_ENABLED=0 go build -trimpath \
    -ldflags="-s -w -X ${MODULE_PATH}/internal/version.Version=${VERSION}" \
    -o /out/harness-provider ./cmd/provider

# Runtime stage: minimal distroless image.
ARG BASE_REGISTRY=gcr.io
FROM ${BASE_REGISTRY}/distroless/static@sha256:d9f9472a8f4541368192d714a995eb1a99bab1f7071fc8bde261d7eda3b667d8

COPY --from=builder /out/harness-provider /usr/local/bin/harness-provider

USER 65532
ENTRYPOINT ["harness-provider"]
```

- [ ] **Step 2: Build the image with default args**

Run: `docker buildx build --load -t provider-harness:test .`
Expected: build succeeds; final line tags `provider-harness:test`. If BuildKit is unavailable, run `docker build --load -t provider-harness:test .` instead.

- [ ] **Step 3: Smoke-test the binary in the runtime image**

Run: `docker run --rm provider-harness:test --help`
Expected: prints the provider's usage/help text and exits non-zero (kingpin `--help` exits with error) — the key check is that it runs, proving the entrypoint and static binary work.

- [ ] **Step 4: Verify version ldflag default**

Expected: prints the provider version. (If `--version` is not a supported flag, verify the build stage log line shows `-X .../internal/version.Version=0.0.0` instead.)

### Task 2: `hack/build-image.sh` pipeline entrypoint

**Files:**
- Create: `hack/build-image.sh`
- Test: run against Task 1's Dockerfile

**Interfaces:**
- Consumes: `Dockerfile` from Task 1 (build args: `BASE_REGISTRY`, `GOPROXY`, `GOSUMDB`, `GONOSUMDB`, `MODULE_PATH`, `VERSION`)
- Produces: executable script `hack/build-image.sh` that prints the final image ref `$REGISTRY/$IMAGE_NAME:$TAG`

- [ ] **Step 1: Create the script**

Write exactly this to `hack/build-image.sh`:

```bash
#!/usr/bin/env bash
set -euo pipefail

# Builds the provider container image with docker buildx.
# All settings come from env vars so the org pipeline can point the build
# at private registries without editing this file.
#
#   REGISTRY        target image registry/org, e.g. harbor.corp.com/harness (default: local)
#   IMAGE_NAME      image name (default: provider-harness)
#   TAG             image tag (default: git describe --always --dirty)
#   PLATFORMS       build platforms (default: linux/amd64,linux/arm64)
#   BASE_REGISTRY   registry hosting golang/distroless base images (default: gcr.io)
#   GOPROXY         Go module proxy (default: https://proxy.golang.org,direct)
#   GOSUMDB         Go checksum db (default: sum.golang.org)
#   GONOSUMDB       comma-separated module paths exempt from the checksum db
#   MODULE_PATH     Go module path for the -X version ldflag (default: current module)
#   VERSION         version baked into the binary (default: $TAG)
#   BUILD_ARGS      extra docker buildx args, e.g. "--push" (default: --load)

REGISTRY=${REGISTRY:-local}
IMAGE_NAME=${IMAGE_NAME:-provider-harness}
TAG=${TAG:-$(git describe --always --dirty 2>/dev/null || echo dev)}
PLATFORMS=${PLATFORMS:-linux/amd64,linux/arm64}
BASE_REGISTRY=${BASE_REGISTRY:-gcr.io}
GOPROXY=${GOPROXY:-https://proxy.golang.org,direct}
GOSUMDB=${GOSUMDB:-sum.golang.org}
GONOSUMDB=${GONOSUMDB:-""}
MODULE_PATH=${MODULE_PATH:-$(go list -m 2>/dev/null || echo github.com/jeremywyx/provider-harness)}
VERSION=${VERSION:-$TAG}
BUILD_ARGS=${BUILD_ARGS:---load}

IMAGE_REF="${REGISTRY}/${IMAGE_NAME}:${TAG}"

docker buildx build ${BUILD_ARGS} \
  --platform "${PLATFORMS}" \
  -t "${IMAGE_REF}" \
  --build-arg BASE_REGISTRY="${BASE_REGISTRY}" \
  --build-arg GOPROXY="${GOPROXY}" \
  --build-arg GOSUMDB="${GOSUMDB}" \
  --build-arg GONOSUMDB="${GONOSUMDB}" \
  --build-arg MODULE_PATH="${MODULE_PATH}" \
  --build-arg VERSION="${VERSION}" \
  -f Dockerfile .

echo "Built ${IMAGE_REF}"
```

- [ ] **Step 2: Make it executable and lint**

Run: `chmod +x hack/build-image.sh && shellcheck hack/build-image.sh`
Expected: exit 0 (or note it as skipped if `shellcheck` is not installed).

- [ ] **Step 3: Run the script end-to-end**

Run: `PLATFORMS=linux/amd64 hack/build-image.sh`
Expected: build succeeds; script prints `Built local/provider-harness:<tag>`.

- [ ] **Step 4: Verify it honors a private-registry config**

Run: `PLATFORMS=linux/amd64 REGISTRY=example.com/harness BASE_REGISTRY="example.com/mirror" GOPROXY="https://proxy.corp.com,off" GONOSUMDB="*" BUILD_ARGS="--load" VERSION=v1.2.3 hack/build-image.sh`
Expected: script invokes buildx with `--build-arg BASE_REGISTRY=example.com/mirror`, `--build-arg GOPROXY=https://proxy.corp.com,off`, `--build-arg GONOSUMDB=*`, and `--build-arg VERSION=v1.2.3` (verified for propagation), and tags the image `example.com/harness/provider-harness:<git-describe>` unless `TAG=v1.2.3` is also set (the image tag is driven by `TAG`, not `VERSION`). (The build itself may fail from an unreachable registry — acceptable; the point is argument propagation. To check propagation without a full build, add `echo "$MODULE_PATH"` debugging or run with `--dry-run` reasoning.)

- [ ] **Step 5: Commit**

```bash

git commit -m "feat: add build-image script for org CI pipeline"
```
